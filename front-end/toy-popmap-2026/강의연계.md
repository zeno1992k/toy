# 강의 연계와 학습 범위

확인일: 2026-10-03 (Asia/Seoul)

강의의 구현 지식을 새 문화 산책 서비스와 연결해 직접 손코딩한다. 아래는 fro1·fro2의 실제 자료 목록과 학습 연결안이며, 학습을 완료했다는 기록이 아니다. 최종 서비스의 실행 스택은 기획.md에서 정하고, 여러 상태·스타일·백엔드 대안은 비교 실습에서 같은 요구사항으로 작성한다.

**확인 상태:** `읽음`은 지정한 파일 본문을 실제 확인했다는 뜻이다. `관련 줄/앞부분 확인`은 부분 확인, `목록/파일명 확인`은 존재 확인이다. 모든 학습 과제는 미완료다. 강의는 2022~2023년 예제이므로 실제 실습 전에 현재 공식 문서와 차이를 확인한다.

## 필수 비교 실습과 완료 기준

- [ ] **동선 초안 상태:** 같은 행사 추가·삭제·순서 변경·필터·파생 합계·복원 요구사항을 Context, Redux, MobX, Recoil, Zustand 각각으로 작성한다. 상태 소유 위치, 변경 방식, 파생 값, 구독/렌더 범위를 비교하고 최종 서비스 선택 이유를 적는다.
- [ ] **EventCard UI:** 같은 데이터·동작·키보드 조작·모바일 조건으로 일반 CSS, Sass, MUI, Emotion, styled-components, Tailwind를 각각 작성한다. 디자인 결과 외에 재사용, 테마, 반응형, 빌드 흐름과 의존성을 비교한다.
- [ ] **같은 행사 메모 CRUD:** Node HTTP/메모리 → Express REST → MongoDB/Mongoose → GraphQL → Firebase 저장소 방식으로 동일한 입력·조회·수정·삭제 요구사항을 구현하고 요청/응답·검증·오류·영속성·접근 제어를 비교한다. 최종 서비스의 Prisma/PostgreSQL 방식과 연결한다.
- [ ] **인증 비교:** Disney Firebase 인증과 당근 next-auth/Prisma 흐름을 읽고 로그인·세션·로그아웃·작성 권한을 같은 시나리오로 구현·검증한다.
- [ ] **데이터와 문의:** 서버 요청과 클라이언트 요청, 직접 fetch/axios와 SWR 조회/변경, 폴링의 상태 흐름을 행사 문의 기능으로 실습한다.
- [ ] **빌드와 배포:** 같은 작은 화면을 Webpack/Vite로 빌드하고 Next 실행 구조와 비교한다. Docker·Actions·S3·CloudFront는 정적 비교 실습과 최종 서버 서비스의 차이를 기록한다.
- [ ] **학습 증거:** 과제마다 읽은 강의 파일, 본인이 쓴 코드, 실행 결과, 실패·수정 이유, 선택 근거를 날짜별 ai-log에 남긴다. 코드 재현 후 요구사항 하나를 바꾸어 원리를 설명한다.

## 근거의 한계와 보강할 부분

- **Firebase:** 이번 Disney 확인은 Nav.js의 signInWithPopup/onAuthStateChanged/signOut 관련 줄과 package.json의 firebase 의존성이다. Firebase 메모 CRUD는 새 비교 실습이며 제공 소스에서 구현을 확인한 기능으로 표시하지 않는다. 저장소/API 선택은 실제 실습 단계에서 공식 문서로 확인한다.
- **SWR·채팅:** ChatClient.tsx에서 refreshInterval: 1000의 폴링 조회, Input.tsx에서 useSWRMutation 사용을 확인했다. socket.io/socket.io-client는 당근 package.json에 존재하지만 이번에 읽은 채팅 구현의 소켓 사용 근거는 확보하지 않았다.
- **테스트:** [client/src/App.test.js](<../reference/fro1/초격차-패키지-한-번에-끝내는-프론트엔드-개발-소스코드/올인원-패키지--만들면서-익히는-react의-모든-것-개발부터-배포까지-with-25개-스택-소스코드-/fastcampus-source-code/1_react/react-context-app/client/src/App.test.js>)는 CRA 기본 ‘learn react’ 검사였다. Jest/Testing Library/user-event 및 Context 서버의 supertest는 package.json 의존성 증거다. 의미 있는 행사·권한·CRUD 테스트를 강의에서 이미 제공했다고 주장하지 않는다. 실습 요구사항에 맞는 검증 과제는 별도로 설계한다.
- **패키지와 사용 코드:** 22개 package.json의 scripts/의존성을 읽었다. 당근의 Cloudinary·bcryptjs·SWR·Socket.IO·지도/폼 라이브러리, MobX decorator의 Babel 플러그인, Webpack의 bundle analyzer 등은 선언을 확인했으며 표에서 본문을 읽었다고 표시한 파일 외의 전체 사용처를 분석한 것은 아니다.
- **기존 기획의 누락:** Disney/당근의 일부 기능과 Next/Tailwind만 실제 구현 대상으로 좁히면 Context·상태 대안·스타일 대안·Node·Express·Mongo·GraphQL·Firebase·빌드 도구·React18·Docker/배포 비교의 직접 구현이 빠진다. 새 학습 계획에서는 위 항목마다 실습과 증거를 둔다.
- **범위 경계:** Vue·Svelte PDF의 존재를 확인했지만 React25 코드 목록과 별도로 관리한다. 노트 본문과 아직 읽지 않은 소스는 각 과제 시작 전에 실제로 읽어 학습 요구사항을 확정한다.
