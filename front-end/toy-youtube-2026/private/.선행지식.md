# YouTube 서비스 프로젝트를 위한 React 선행 지식

이 문서는 React 문법을 전부 외우기 위한 자료가 아니다. **YouTube와 비슷한 서비스를 직접 설계하고 구현할 때 무엇을 알아야 하는지**를 순서대로 정리한 안내서다.

처음부터 완벽한 YouTube를 만들려고 하지 말고 다음 흐름을 먼저 완성하는 것이 목표다.

> 데이터를 가져온다 → 목록으로 보여준다 → 사용자가 영상을 선택한다 → 상세 화면을 보여준다 → 검색한다

---

## 1. 먼저 알아야 할 JavaScript

React는 JavaScript 위에서 동작한다. 아래 문법이 낯설다면 React와 함께 조금씩 복습하면 된다.

### 변수와 함수

```js
const title = "고양이 영상";

function getTitle(video) {
  return video.title;
}

const getChannel = (video) => video.channelTitle;
```

- `const`, `let`의 차이
- 일반 함수와 화살표 함수
- 함수의 매개변수와 반환값
- 콜백 함수

### 객체와 배열

YouTube API의 응답은 객체와 배열이 중첩된 형태다.

```js
const video = {
  id: "abc123",
  title: "React 공부하기",
  channelTitle: "Zeno Channel",
};

const videos = [video];
```

특히 자주 사용하는 배열 메서드는 다음과 같다.

```js
videos.map((video) => video.title);       // 데이터를 화면 요소로 변환
videos.filter((video) => video.id !== id); // 조건에 맞는 데이터만 선택
videos.find((video) => video.id === id);   // 하나의 데이터 찾기
```

### 구조 분해와 전개 문법

```js
const { title, channelTitle } = video;
const updatedVideo = { ...video, title: "변경된 제목" };
const nextVideos = [...videos, newVideo];
```

React에서는 기존 객체나 배열을 직접 수정하지 않고 새로운 값을 만드는 것이 중요하다.

### 모듈

```js
export function VideoCard() {}
import { VideoCard } from "./VideoCard";
```

컴포넌트와 API 코드를 파일별로 나눌 때 사용한다.

### 비동기 처리

```js
async function fetchVideos() {
  const response = await fetch("API 주소");
  const data = await response.json();
  return data;
}
```

- `Promise`
- `async` / `await`
- `try` / `catch`
- HTTP 요청과 JSON 응답

이 부분은 YouTube API를 사용할 때 반드시 필요하다.

## 2. React의 핵심 사고방식

React 화면은 다음 관계로 생각하면 이해하기 쉽다.

```text
화면(UI) = 현재 상태(state)를 화면으로 표현한 결과
```

사용자가 검색하거나 영상을 선택하면 상태가 바뀌고, React가 변경된 상태에 맞춰 화면을 다시 그린다. 직접 HTML을 찾아서 수정하는 방식과 다르다.

```jsx
function App() {
  const [keyword, setKeyword] = useState("");

  return <h1>현재 검색어: {keyword}</h1>;
}
```

핵심 흐름은 다음과 같다.

```text
사용자 행동 → 이벤트 처리 → 상태 변경 → 화면 다시 렌더링
```

## 3. JSX

JSX는 JavaScript 안에서 UI 구조를 표현하는 문법이다.

```jsx
function VideoTitle() {
  const title = "React 강의";

  return <h2 className="video-title">{title}</h2>;
}
```

알아야 할 내용:

- JavaScript 값은 `{}` 안에 작성한다.
- HTML의 `class` 대신 `className`을 사용한다.
- 여러 요소를 반환할 때 하나의 부모 요소로 감싼다.
- JSX 태그는 반드시 닫는다.

```jsx
return (
  <>
    <Header />
    <VideoList />
  </>
);
```

## 4. 컴포넌트

컴포넌트는 화면을 역할별로 분리한 함수다. 이름은 대문자로 시작한다.

```jsx
function VideoCard() {
  return <article>영상 카드</article>;
}
```

YouTube 프로젝트는 다음처럼 나눌 수 있다.

```text
App
├─ Header
│  └─ SearchForm
├─ VideoList
│  └─ VideoCard 여러 개
└─ VideoDetail
```

컴포넌트를 나누는 기준:

- 반복해서 사용되는 UI인가?
- 하나의 분명한 역할이 있는가?
- 코드가 너무 길어졌는가?
- 독립적으로 테스트하거나 수정할 가치가 있는가?

처음부터 너무 잘게 쪼갤 필요는 없다. 먼저 만들고, 반복이나 역할이 보일 때 분리해도 된다.

## 5. Props: 부모가 자식에게 전달하는 값

부모 컴포넌트는 자식에게 데이터와 함수를 전달할 수 있다.

```jsx
function VideoCard({ video, onSelect }) {
  return (
    <button onClick={() => onSelect(video)}>
      {video.title}
    </button>
  );
}

function VideoList({ videos, onSelect }) {
  return videos.map((video) => (
    <VideoCard key={video.id} video={video} onSelect={onSelect} />
  ));
}
```

기억할 점:

- props는 읽기 전용이다.
- 자식은 전달받은 props를 직접 변경하지 않는다.
- 자식에서 부모의 상태를 바꾸려면 부모가 전달한 함수를 호출한다.

## 6. useState: 화면이 기억해야 하는 값

`useState`는 사용자 행동이나 API 응답에 따라 바뀌며, 화면에도 영향을 주는 값을 저장한다.

```jsx
const [keyword, setKeyword] = useState("");
const [videos, setVideos] = useState([]);
const [selectedVideo, setSelectedVideo] = useState(null);
const [isLoading, setIsLoading] = useState(false);
const [error, setError] = useState(null);
```

YouTube 프로젝트의 대표적인 상태:

| 상태 | 의미 | 초기값 예시 |
| --- | --- | --- |
| `keyword` | 입력 중인 검색어 | `""` |
| `videos` | 화면에 표시할 영상 목록 | `[]` |
| `selectedVideo` | 사용자가 선택한 영상 | `null` |
| `isLoading` | API 요청 중인지 여부 | `false` |
| `error` | 요청 실패 정보 | `null` |

### 상태를 설계할 때 묻기

1. 이 값이 실행 중에 변하는가?
2. 이 값이 변하면 화면도 달라져야 하는가?
3. 다른 상태로부터 계산할 수 없는가?

세 질문에 해당한다면 상태일 가능성이 높다.

다른 값에서 계산할 수 있다면 별도 상태로 저장하지 않는 편이 좋다.

```js
const hasVideos = videos.length > 0;
```

### 상태는 직접 수정하지 않는다

```js
// 피해야 하는 방식
videos.push(newVideo);

// 새로운 배열을 전달한다
setVideos([...videos, newVideo]);
```

이전 상태를 기준으로 변경한다면 함수 형태가 안전하다.

```js
setCount((previousCount) => previousCount + 1);
```

## 7. 이벤트 처리와 폼

검색창을 만들려면 입력 이벤트와 제출 이벤트를 다뤄야 한다.

```jsx
function SearchForm({ onSearch }) {
  const [keyword, setKeyword] = useState("");

  function handleSubmit(event) {
    event.preventDefault();
    onSearch(keyword);
  }

  return (
    <form onSubmit={handleSubmit}>
      <input
        value={keyword}
        onChange={(event) => setKeyword(event.target.value)}
      />
      <button type="submit">검색</button>
    </form>
  );
}
```

위 입력창처럼 React 상태가 입력값을 관리하는 방식을 **제어 컴포넌트**라고 한다.

알아야 할 이벤트:

- `onClick`
- `onChange`
- `onSubmit`
- `event.target.value`
- `event.preventDefault()`

## 8. 목록 렌더링과 key

API에서 받은 배열은 `map`을 사용해 컴포넌트 목록으로 만든다.

```jsx
function VideoList({ videos }) {
  return (
    <section>
      {videos.map((video) => (
        <VideoCard key={video.id} video={video} />
      ))}
    </section>
  );
}
```

`key`는 React가 각 항목을 구별하기 위한 값이다.

- 데이터의 고유한 ID를 사용한다.
- 가능하면 배열의 순번인 `index`를 key로 사용하지 않는다.
- 같은 목록 안에서 중복되지 않아야 한다.

## 9. 조건부 렌더링

API 화면에는 성공한 결과만 존재하지 않는다. 로딩, 오류, 빈 결과도 UI로 설계해야 한다.

```jsx
if (isLoading) return <p>영상을 불러오는 중입니다.</p>;
if (error) return <p>영상을 불러오지 못했습니다.</p>;
if (videos.length === 0) return <p>검색 결과가 없습니다.</p>;

return <VideoList videos={videos} />;
```

UI 상태를 최소한 다음 네 가지로 나눠 생각한다.

```text
로딩 중 / 성공 / 결과 없음 / 실패
```

## 10. useEffect: 외부 시스템과 동기화하기

`useEffect`는 렌더링 이후 외부 시스템과 동기화할 때 사용한다. 이 프로젝트에서는 최초 API 요청이 대표적인 예다.

```jsx
useEffect(() => {
  async function loadPopularVideos() {
    const videos = await fetchPopularVideos();
    setVideos(videos);
  }

  loadPopularVideos();
}, []);
```

의존성 배열에 따라 실행 시점이 달라진다.

```jsx
useEffect(() => {
  // 렌더링 후마다 실행
});

useEffect(() => {
  // 처음 화면에 나타난 뒤 실행
}, []);

useEffect(() => {
  // keyword가 바뀐 뒤 실행
}, [keyword]);
```

주의할 점:

- 클릭으로 검색하는 동작은 클릭 이벤트에서 직접 처리할 수도 있다.
- 계산할 수 있는 값을 만들기 위해 무조건 effect를 쓰지 않는다.
- effect 안에서 사용하는 외부 값은 의존성 배열과 관계가 있다.
- 개발 모드의 `StrictMode`에서는 문제를 찾기 위해 effect가 두 번 실행되는 것처럼 보일 수 있다.
- 타이머, 이벤트 구독 등이 있다면 cleanup 함수로 정리한다.

```jsx
useEffect(() => {
  const timerId = setInterval(refresh, 1000);

  return () => clearInterval(timerId);
}, []);
```

`useEffect`를 단순히 “페이지가 열릴 때 실행하는 함수”로만 외우지 않는 것이 중요하다.

## 11. API 호출과 요청 상태

API 코드는 UI 컴포넌트와 분리하면 읽고 수정하기 편하다.

```js
// services/youtube.js
export async function searchVideos(keyword) {
  const response = await fetch(`API_URL&q=${encodeURIComponent(keyword)}`);

  if (!response.ok) {
    throw new Error("영상 검색에 실패했습니다.");
  }

  const data = await response.json();
  return data.items;
}
```

컴포넌트에서는 요청 상태를 관리한다.

```jsx
async function handleSearch(keyword) {
  try {
    setIsLoading(true);
    setError(null);

    const nextVideos = await searchVideos(keyword);
    setVideos(nextVideos);
  } catch (error) {
    setError(error);
  } finally {
    setIsLoading(false);
  }
}
```

알아야 할 개념:

- 요청 URL과 query parameter
- HTTP 성공 여부 확인
- JSON 변환
- 로딩과 오류 처리
- 검색어의 URL 인코딩
- API 응답을 UI가 사용하기 좋은 형태로 변환하기

실제 API를 붙이기 전에는 작은 목업 데이터로 UI부터 구현해도 좋다.

## 12. YouTube Data API에서 알아야 할 것

YouTube 화면을 만든다고 해서 처음부터 모든 API를 사용할 필요는 없다. 보통 아래 기능부터 시작한다.

- 인기 영상 조회
- 키워드로 영상 검색
- 영상 상세 정보 조회
- 필요하다면 관련 영상 또는 채널 정보 조회

API 응답을 사용할 때는 다음을 확인한다.

```text
영상 ID는 어디에 있는가?
제목과 채널명은 어디에 있는가?
썸네일 크기별 URL은 어디에 있는가?
검색 응답과 인기 영상 응답의 ID 구조가 같은가?
다음 페이지 토큰은 어디에 있는가?
```

특히 YouTube API는 요청 종류에 따라 영상 ID의 위치가 다를 수 있다. 컴포넌트 곳곳에서 원본 응답 구조를 처리하기보다 서비스 함수에서 동일한 형태로 정리하면 편하다.

```js
function normalizeVideo(item) {
  return {
    id: typeof item.id === "string" ? item.id : item.id.videoId,
    title: item.snippet.title,
    channelTitle: item.snippet.channelTitle,
    thumbnail: item.snippet.thumbnails.medium.url,
  };
}
```

API 키는 `.env`에 보관하고 `.gitignore`로 제외해야 한다. 다만 프런트엔드에서 사용하는 키는 사용자에게 완전히 숨길 수 없으므로, Google Cloud Console에서 허용 도메인과 사용할 API를 제한해야 한다.

## 13. 상태를 어디에 둘 것인가

여러 컴포넌트가 같은 상태를 사용한다면 가장 가까운 공통 부모가 상태를 관리한다. 이를 **상태 끌어올리기**라고 한다.

예를 들어:

```text
App
├─ SearchForm  ─ 검색어를 App에 전달
├─ VideoList  ─ App의 videos를 전달받음
└─ VideoDetail ─ App의 selectedVideo를 전달받음
```

`VideoList`와 `VideoDetail` 모두 선택된 영상과 관계가 있으므로 `selectedVideo`는 `App`에서 관리하는 것이 자연스럽다.

판단 기준:

- 한 컴포넌트만 사용하는 값이면 그 컴포넌트 가까이에 둔다.
- 여러 형제가 함께 사용하는 값이면 공통 부모로 올린다.
- 모든 상태를 무조건 `App`에 몰아넣지 않는다.

작은 프로젝트에서는 먼저 props로 구현하자. Context나 별도 상태 관리 라이브러리는 실제로 전달 단계가 너무 깊어질 때 배워도 늦지 않다.

## 14. 페이지 이동과 라우팅

한 화면 안에서 영상 목록과 상세를 바꾸는 방식으로 먼저 만들 수 있다. 이후 URL로 페이지를 구분하고 싶다면 React Router를 사용한다.

```text
/                 홈 또는 인기 영상
/search?q=react   검색 결과
/watch/abc123     영상 상세
```

라우팅 단계에서 알아볼 내용:

- `BrowserRouter`
- `Routes`, `Route`
- `Link`
- URL parameter와 query string
- 뒤로 가기와 새로고침에도 유지되는 화면

라우팅은 React의 필수 기초라기보다 프로젝트를 실제 서비스처럼 만드는 다음 단계다.

## 15. CSS와 반응형 레이아웃

React 프로젝트라도 기본적인 CSS가 필요하다.

- Flexbox: 헤더와 가로 배치
- Grid: 영상 카드 목록
- 미디어 쿼리: 모바일 대응
- `aspect-ratio`: 썸네일과 영상 비율
- `object-fit`: 이미지가 영역에 맞게 표시되도록 처리
- hover, focus 등 상호작용 상태

```css
.video-grid {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(260px, 1fr));
  gap: 24px 16px;
}

.thumbnail {
  width: 100%;
  aspect-ratio: 16 / 9;
  object-fit: cover;
}
```

디자인할 때는 색상보다 먼저 정보의 우선순위와 배치를 정한다.

## 17. 추천 구현 순서

한 번에 모든 기능을 만들지 말고 매 단계에서 작동하는 결과를 확인한다.

### 1단계: 정적인 화면

- 직접 작성한 목업 영상 3개 준비
- 헤더, 검색창, 영상 카드, 목록 구현
- 반응형 Grid 적용

### 2단계: props와 이벤트

- 영상 정보를 props로 전달
- 목록을 `map`으로 출력
- 카드를 클릭하면 선택된 영상 표시

### 3단계: 상태

- 검색 입력값 관리
- 영상 목록 관리
- 선택된 영상 관리
- 로딩, 오류 상태 설계

### 4단계: API

- API 서비스 함수 분리
- 최초 인기 영상 요청
- 검색 제출 시 검색 API 요청
- 응답 데이터를 동일한 영상 형태로 변환

### 5단계: 예외 상황

- 로딩 UI
- 오류 UI와 재시도
- 검색 결과 없음
- 이미지 로딩 실패
- 빈 검색어 제출 방지

### 6단계: 서비스다운 기능

- React Router로 상세 URL 구성
- 페이지네이션 또는 더 보기
- 검색어 URL 유지
- 영상 플레이어
- 접근성과 키보드 조작 확인

## 18. 처음에는 몰라도 되는 것

아래 기술은 프로젝트 규모가 커질 때 유용하지만 첫 버전의 필수 조건은 아니다.

- Redux, Zustand 같은 전역 상태 관리
- 복잡한 Context 사용
- `useReducer`
- 성능 최적화를 위한 `useMemo`, `useCallback`
- TypeScript
- React Query 또는 TanStack Query
- 백엔드 서버와 데이터베이스
- 무한 스크롤

필요해지기 전에 미리 넣으면 React의 기본 데이터 흐름을 이해하기 더 어려울 수 있다.

## 19. 직접 설계하기 전에 적어볼 질문

코드를 작성하기 전에 종이나 Markdown에 다음 질문의 답을 적어본다.

1. 사용자가 처음 접속하면 무엇을 보는가?
2. 사용자가 할 수 있는 행동은 무엇인가?
3. 행동할 때 어떤 값이 바뀌는가?
4. 어떤 API 요청이 필요한가?
5. 로딩 중에는 무엇을 보여주는가?
6. 요청에 실패하면 무엇을 보여주는가?
7. 검색 결과가 없다면 무엇을 보여주는가?
8. 모바일에서는 목록과 상세 화면을 어떻게 배치하는가?

그리고 화면별로 다음 표를 직접 작성해보면 상태 설계가 쉬워진다.

| 화면/컴포넌트 | 필요한 데이터 | 사용자 행동 | 바뀌는 상태 |
| --- | --- | --- | --- |
| SearchForm | 입력 중인 검색어 | 입력, 제출 | `keyword` |
| VideoList | 영상 목록 | 카드 선택 | `selectedVideo` |
| VideoDetail | 선택된 영상 | 닫기 또는 뒤로 가기 | `selectedVideo` |

## 20. 학습 완료 확인표

설명을 읽는 것보다 직접 작은 코드를 작성해보는 것이 중요하다.

- [ ] JSX 안에 변수와 조건을 표현할 수 있다.
- [ ] 컴포넌트를 만들고 다른 파일에서 불러올 수 있다.
- [ ] 부모가 자식에게 props를 전달하는 흐름을 설명할 수 있다.
- [ ] `useState`로 입력값과 배열을 관리할 수 있다.
- [ ] 이벤트를 통해 부모 상태를 변경할 수 있다.
- [ ] 배열을 `map`으로 렌더링하고 적절한 key를 줄 수 있다.
- [ ] 로딩, 성공, 빈 결과, 오류 UI를 구분할 수 있다.
- [ ] `useEffect`가 필요한 경우와 필요하지 않은 경우를 구분할 수 있다.
- [ ] `fetch`, `async/await`, `try/catch`로 API를 호출할 수 있다.
- [ ] API 응답을 컴포넌트용 데이터 형태로 변환할 수 있다.
- [ ] 어떤 컴포넌트가 상태를 소유해야 하는지 이유를 설명할 수 있다.
- [ ] API 키를 소스 코드와 Git에 직접 넣으면 안 되는 이유를 안다.

## 핵심 요약

이 프로젝트를 시작하기 위해 가장 중요한 것은 다음 다섯 가지다.

1. **컴포넌트**로 화면의 역할을 나눈다.
2. **props**로 부모의 데이터와 함수를 자식에게 전달한다.
3. **state**로 변하는 값을 관리한다.
4. **이벤트**가 상태를 바꾸고, 바뀐 상태가 화면을 다시 만든다.
5. **effect와 비동기 함수**로 외부 API와 동기화한다.

모든 지식을 완벽히 공부한 뒤 프로젝트를 시작할 필요는 없다. 먼저 목업 데이터로 작은 화면을 만들고, 필요한 개념이 등장할 때 이 문서로 돌아와 확인하는 방식이 가장 현실적이다.
