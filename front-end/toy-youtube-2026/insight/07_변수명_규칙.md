# 07. 변수명과 HTML·CSS·React 이름 규칙

## 1. 문법과 관례를 구분하기

- **문법**: 어기면 오류가 나거나 의도한 의미로 동작하지 않는 규칙.
- **관례**: 팀이 일관성을 위해 선택하는 이름 방식.
- 아래는 이 프로젝트에서 쓰기 좋은 권장 관례다. 모든 회사의 공통 규칙은 아니다.
- 역할과 의미가 드러나는 영어 이름을 사용한다. 한글 설명은 주석·문서·사용자 UI에 적어도 된다.

## 2. 표기법

| 방식 | 예시 | 권장 용도 |
| --- | --- | --- |
| camelCase | `searchQuery` | JS 변수·함수·객체 속성 |
| PascalCase | `VideoCard` | React 컴포넌트·클래스 |
| kebab-case | `video-card` | HTML id·CSS class·CSS 변수 |
| UPPER_SNAKE_CASE | `MAX_RESULTS` | 고정 설정 상수 |
| snake_case | `video_id` | 외부 API가 사용하는 경우 원본 필드 등에 유지 |

JavaScript에서 `const video-title = ...`처럼 하이픈을 변수명에 쓸 수는 없다. `-`는 연산자로 해석된다. 객체에 문자열 키로 저장하는 경우는 별개다.

## 3. HTML id

- 한 문서 안에서 고유해야 한다.
- 이 프로젝트는 소문자 kebab-case를 사용한다.
- 공백을 넣지 않는다.
- 숫자로 시작하는 등 CSS 이스케이프가 필요한 이름은 피하면 편하다.
- label·ARIA 연결, 페이지 내 이동 등 식별이 필요할 때 사용한다.

```jsx
<label htmlFor="video-search">검색어</label>
<input id="video-search" type="search" />

<h2 id="subscription-heading">구독</h2>
<nav aria-labelledby="subscription-heading">...</nav>
```

반복 카드마다 `id="video-card"`를 넣으면 중복된다. 반복 스타일에는 className을 사용한다.

참고: [MDN id](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/id).

## 4. HTML class와 React className

- HTML에서는 `class`, JSX에서는 `className`.
- 이 프로젝트는 kebab-case로 통일한다.
- 같은 클래스는 여러 요소에 재사용할 수 있다.
- 위치·색상만보다 역할이 드러나는 이름을 먼저 고려한다.

```jsx
<header className="site-header">...</header>
<aside className="sidebar">...</aside>
<main className="main-content">...</main>
<article className="video-card">...</article>
```

| 모호한 이름 | 의미가 드러나는 예 |
| --- | --- |
| `box1` | `video-card` |
| `left` | `sidebar` |
| `text2` | `video-card-title` |
| `red-button` | `subscribe-button` |

유틸리티 클래스처럼 위치·색상을 의도적으로 표현하는 방식도 있다. 위 표는 역할 중심의 컴포넌트 스타일 기준이다.

## 5. BEM은 선택 사항

컴포넌트 규모가 커지면 다음 방식도 사용할 수 있다.

```text
video-card
video-card__thumbnail
video-card__title
video-card--compact
```

- block: 독립 구성 요소.
- element: 구성 요소 내부 부분.
- modifier: 변형 상태.
- 지금은 단순 kebab-case만 사용해도 된다. 중간에 여러 방식이 섞이지 않게 한다.

## 6. CSS 관련 이름

```css
:root {
  --color-text: #111111;
  --sidebar-width: 220px;
  --header-height: 64px;
}

.app {
  grid-template-areas:
    "header header"
    "sidebar content";
}

.site-header { grid-area: header; }
```

- 사용자 정의 속성은 `--`로 시작한다.
- 클래스 `site-header`와 영역 이름 `header`는 자동 연결되지 않는다.
- `grid-area`로 직접 연결한다.
- `@layer reset, base, components;`의 레이어 이름은 개발자가 정한다.
- `container-name: video-area;`의 이름도 개발자가 정한다.
- `role="group"`의 group은 임의 이름이 아닌 정해진 역할이다.

## 7. JavaScript 변수

값의 의미가 드러나는 명사·명사구를 camelCase로 작성한다.

```js
const videoTitle = "React 입문";
const selectedVideoId = "example";
const searchQuery = "react";
const pageToken = null;
```

- `data`, `value`, `item`이 항상 나쁜 것은 아니지만 범위가 넓으면 의미를 구체화한다.
- 같은 의미에 `keyword`, `query`, `searchText`를 섞어 쓰지 않는다.
- 서로 다른 개념이라면 구분한다: 입력 중인 값과 제출한 값.

```js
const inputQuery = "react hooks";     // 현재 작성 중인 값
const submittedQuery = "react";      // 현재 결과의 검색어
```

## 8. 단수·복수와 객체

```js
const video = { id: "example", title: "React 입문" };
const videos = [video];
const videoIds = videos.map((video) => video.id);
const videoCount = videos.length;
```

- 하나는 `video`, 여러 개는 `videos`.
- ID 목록은 `videoIds`.
- 개수는 `videoCount`.
- 객체 속성은 보통 camelCase.
- API 원본 필드는 외부 계약을 따른다. 바꾸려면 서비스 경계에서 명시적으로 변환한다.

## 9. Boolean 이름

참·거짓을 읽었을 때 문장처럼 이해되는 이름을 쓴다.

- `isLoading`: 로딩 중인가?
- `isSidebarOpen`: 사이드바가 열렸는가?
- `hasNextPage`: 다음 페이지가 있는가?
- `canSubmit`: 제출 가능한가?
- `shouldRefresh`: 새로고침해야 하는가?

`isNotClosed`처럼 부정을 겹치기보다 `isOpen`처럼 단순하게 정한다.

JSX의 `disabled`, `checked` 등 기존 HTML·React 속성 이름은 그대로 사용한다.

## 10. 숫자·날짜·단위

- `durationSeconds`: 영상 길이(초).
- `requestTimeoutMs`: 요청 제한 시간(밀리초).
- `thumbnailWidthPx`: 이미지 너비(px).
- `publishedAt`: 게시 시각.
- `retryCount`: 재시도 횟수.

문맥상 단위가 불명확하면 이름에 포함한다. 모든 숫자에 무조건 단위를 붙여야 하는 것은 아니다.

## 11. 상수와 const

```js
const MAX_RESULTS = 20;
const REQUEST_TIMEOUT_MS = 5000;
const YOUTUBE_API_BASE_URL = "https://www.googleapis.com/youtube/v3";
```

모듈의 고정 설정값은 UPPER_SNAKE_CASE를 사용할 수 있다.

하지만 `const`라고 모두 대문자는 아니다.

```js
const videoTitle = video.title;
const videos = response.items;
```

const는 변수의 재할당을 막는다. 객체·배열 내부까지 불변으로 만드는 것은 아니다.

## 12. 함수명

동사와 대상이 드러나는 camelCase 이름을 사용한다.

| 의도 | 예시 |
| --- | --- |
| 검색 | `searchVideos` |
| 외부 요청 | `fetchPopularVideos` |
| 선택 | `selectVideo` |
| 열기·닫기 | `openSidebar`, `closeSidebar` |
| 상태 반전 | `toggleSidebar` |
| 형식 변환 | `formatDuration` |
| 검증 | `validateSearchQuery` |
| 응답 형태 정리 | `normalizeVideo` |

`get`과 `fetch`의 구분은 관례다. 이 프로젝트에서는 fetch를 네트워크 요청 함수에 사용하면 구분하기 쉽다.

`processData`, `doSomething`, `func1`처럼 동작을 알기 어려운 이름은 피한다.

## 13. 이벤트: handle과 on

- 구현하는 이벤트 처리 함수: `handleSearchSubmit`.
- 자식에게 전달하는 이벤트 prop: `onSearch`.
- 이 구분은 관례이며 React가 강제하는 문법은 아니다.

```jsx
function SearchForm({ onSearch }) {
  function handleSubmit(event) {
    event.preventDefault();
    onSearch();
  }

  return (
    <form onSubmit={handleSubmit}>
      <button type="submit">검색</button>
    </form>
  );
}
```

이 예시는 이름 관계만 보여준다. 실제 검색어 상태와 요청은 별도 구현한다.

- `onSubmit={handleSubmit}`: 이벤트 때 호출할 함수를 전달.
- `onSubmit={handleSubmit()}`: 렌더링 도중 바로 호출하므로 일반적인 이벤트 연결 의도와 다름.

## 14. React 컴포넌트

- 대문자로 시작하는 PascalCase.
- 역할이 드러나는 명사구.
- 사용자 컴포넌트와 소문자 HTML 태그를 구분한다.

```jsx
function VideoCard() {
  return <article>영상 정보</article>;
}
```

추천 예: `Header`, `Sidebar`, `SearchForm`, `VideoList`, `VideoCard`, `VideoPlayer`.

`Content`도 가능하다. 페이지가 늘면 `HomePage`, `SearchPage`, `WatchPage`처럼 구체화할 수 있다.

참고: [React 컴포넌트 작성](https://react.dev/learn/your-first-component).

## 15. React state와 setter

```jsx
const [videos, setVideos] = useState([]);
const [selectedVideoId, setSelectedVideoId] = useState(null);
const [isSidebarOpen, setIsSidebarOpen] = useState(false);
```

- 상태 이름은 값의 의미를 나타낸다.
- setter는 `set + 상태 이름` 형태.
- setter의 실제 값은 이름보다 중요하므로 정확한 타입을 전달한다.
- `videos.length`처럼 계산 가능한 값을 이름 규칙 때문에 별도 state로 만들지 않는다.

## 16. Hook·ref·props

- 커스텀 Hook: `useVideos`, `useLocalStorage`.
- ref 변수: `searchInputRef`, `playerRef`.
- 데이터 prop: `video`, `videos`, `selectedVideoId`.
- 이벤트 prop: `onSelect`, `onSearch`.
- Hook이 아닌 일반 도우미에는 use 접두사를 붙이지 않는다.
- Hook 이름을 지었다고 자동으로 상태 관리 기능이 생기는 것은 아니다.

ref 예제:

```jsx
const searchInputRef = useRef(null);
<input ref={searchInputRef} type="search" aria-label="검색어" />
```

useRef는 필요할 때 배우면 된다. 지금 모든 DOM 요소에 ref를 붙일 필요는 없다.

## 17. 파일과 폴더

이 프로젝트에서 사용할 수 있는 일관된 예시다.

```text
src/
├─ App.jsx
├─ App.css
├─ index.css
├─ components/
│  ├─ VideoCard.jsx
│  └─ VideoCard.css
├─ pages/
│  └─ WatchPage.jsx
├─ hooks/
│  └─ useVideos.js
├─ services/
│  └─ youtube.js
└─ utils/
   └─ formatDuration.js
```

- 컴포넌트 파일: PascalCase.
- Hook 파일: use로 시작하는 camelCase.
- 일반 함수 파일: camelCase 또는 팀이 정한 방식으로 통일.
- 폴더: 소문자, 여러 단어면 kebab-case를 선택할 수 있다.
- 문서는 `06_커밋메시지_규칙.md`처럼 번호와 한글 제목도 괜찮다.
- import 경로의 대소문자를 실제 파일명과 맞춘다. 운영체제에 따라 대소문자 처리 차이가 있다.
- 폴더를 전부 미리 만들 필요는 없다.

## 18. 기타 자주 만나는 이름

- 환경 변수: `YOUTUBE_API_KEY`처럼 도구의 규칙을 따른다.
- Vite의 클라이언트 환경 변수는 비밀 보관소가 아니다. 프런트엔드에 포함된 값은 확인 가능하다.
- URL: `/watch/:videoId`처럼 역할을 드러내는 경로. 실제 라우터 문법에 맞춘다.
- API가 정한 필드·쿼리 이름: 임의로 바꾸지 않는다.
- 리스트의 React `key`: 안정적인 데이터 ID. 클래스명·HTML id와 다른 개념이다.
