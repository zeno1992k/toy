# 02. SEO — 검색엔진 최적화

## 1. 무엇을 하는가?

SEO(Search Engine Optimization)는 검색엔진이 페이지를 발견하고 내용을 이해하도록 개선하는 작업이다. 검색 결과의 상위 노출이나 색인을 보장하지 않는다.

- **크롤링**: 페이지와 자원을 가져오는 과정.
- **렌더링**: HTML·CSS·JavaScript로 화면 내용을 구성하는 과정.
- **색인**: 이해한 내용을 검색에 활용하도록 저장하는 과정.
- **순위 결정**: 검색어에 맞는 결과의 순서를 정하는 과정.

접근성 속성을 많이 붙이는 것과 SEO는 같은 일이 아니다.

## 2. 문서 제목과 요약

```html
<title>Zeno Tube — 영상 탐색</title>
<meta name="description" content="관심 있는 영상을 검색하고 시청할 수 있는 Zeno Tube입니다." />
```

- `<title>`: 브라우저 탭 등에 나타나는 문서 제목.
- `description`: 페이지 내용을 요약한 메타 정보.
- 검색 결과에 지정한 제목·요약이 그대로 표시된다는 보장은 없다.
- 홈·영상 상세처럼 내용이 다르면 문서 제목도 그 내용을 반영한다.
- 요소의 `title="..."` 툴팁과 문서의 `<title>`은 다르다.

참고: [Google SEO 시작 가이드](https://developers.google.com/search/docs/fundamentals/seo-starter-guide).

## 3. 콘텐츠와 링크

- 주제와 하위 내용을 제목으로 나눈다.
- 제목 태그는 글자 크기가 아닌 내용 구조에 맞게 선택한다.
- 링크 문구는 목적지를 설명한다.
- 이미지를 텍스트 대용으로만 사용하지 않는다.
- 중요한 영상 정보는 읽을 수 있는 제목·채널명·설명으로 제공한다.

```jsx
<a href="/watch/example-video">React 상태 관리 입문</a>
```

위 ID와 제목은 구조 설명용 예시다. 실제 영상 데이터로 연결한다.

페이지 이동은 실제 URL이 있는 링크를 사용한다. JavaScript 클릭 이벤트만 있는 div는 탐색용 링크를 대신하기 어렵다.

## 4. React 프로젝트에서 확인할 부분

Google은 JavaScript를 렌더링할 수 있지만 모든 봇이 동일하지 않다. 화면이 내 브라우저에 보이는 것만으로 색인을 보장하지 않는다.

- 상세 URL 직접 접속과 새로고침이 동작하는가?
- API 오류로 제목·설명이 계속 비어 있지는 않은가?
- 필요한 JavaScript와 데이터에 접근 가능한가?
- 각 화면의 제목과 URL이 맞는가?
- 존재하지 않는 영상·경로를 정상 콘텐츠처럼 처리하지 않는가?

서버 렌더링·사전 렌더링은 검토할 수 있는 방법이지만, 이 학습 프로젝트에서 바로 도입해야 할 필수 조건은 아니다.

참고: [Google JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics).

## 5. 영상 서비스에서 생각할 것

시청 페이지에는 실제 재생 가능한 영상과 그 영상의 정보를 중심으로 구성한다. 목록 페이지와 시청 페이지의 목적은 다르다.

- 영상 ID에 대응하는 상세 주소.
- 영상 제목과 실제 플레이어의 일치.
- 접근 가능한 썸네일.
- 설명과 원본 영상 링크.
- 조회·재생 불가 상황의 안내.

`VideoObject` 같은 구조화 데이터는 실제 보이는 내용과 정확히 일치할 때 검토한다. 존재하지 않는 조회수·길이·작성자를 만들어 넣지 않는다. 구조화 데이터를 넣어도 검색의 특별한 표시가 보장되지는 않는다.

참고: [Google 영상 SEO](https://developers.google.com/search/docs/appearance/video).

## 6. 크롤링·색인 관련 용어

- `robots.txt`: 크롤러의 접근 규칙. 파일을 비공개로 보호하는 장치가 아니다.
- `noindex`: 검색 색인 제외 지시. 크롤러가 그 지시를 읽을 수 있어야 한다.
- `sitemap.xml`: 발견시키려는 URL을 제공하는 목록.
- `canonical`: 중복 URL 중 대표 주소를 알리는 정보.
- `Search Console`: 배포한 사이트의 검색 상태와 렌더링 결과 등을 확인하는 도구.

모든 페이지의 canonical을 무조건 홈으로 지정하지 않는다. 검색 결과나 개인 화면까지 무조건 색인 대상으로 만들 필요도 없다.

## 7. 이번 프로젝트의 적용 순서

다음은 학습용 제안이다.

1. 문서 언어, 홈 제목, 서비스 설명을 작성한다.
2. 헤더·본문과 링크 구조를 만든다.
3. 실제 API 제목·설명을 표시한다.
4. 상세 URL과 페이지별 제목을 연결한다.
5. 모바일 배치와 이미지 크기·로딩을 점검한다.
6. 배포 후 색인 의도와 실제 렌더링 결과를 확인한다.
