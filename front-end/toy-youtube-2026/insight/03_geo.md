# 03. GEO — 생성형 엔진 최적화

## 1. 의미

GEO(Generative Engine Optimization)는 AI 검색·답변에서 콘텐츠가 이해되고 언급·인용될 수 있도록 개선하는 접근을 가리킨다.

HTML이나 CSS처럼 하나의 표준 문법이 아니다. 서비스별 수집 방식과 노출 기준이 다르며, 모든 AI 서비스에 통하는 확정 공식은 없다.

## 2. SEO와의 관계

| 구분 | 관심 대상 |
| --- | --- |
| SEO | 검색엔진의 발견·이해·검색 결과 노출 |
| GEO | AI 기반 검색·답변에서의 이해·참조·인용 |

Google의 AI 검색 기능에도 기본 SEO 원칙이 적용된다. 특수한 ARIA 속성이나 AI용 문구를 넣는다고 인용이 보장되지는 않는다.

이 설명은 Google의 공개 가이드를 근거로 한 것이며 다른 모든 서비스에 동일한 규칙이 적용된다는 뜻은 아니다.

참고: [Google AI 기능과 웹사이트](https://developers.google.com/search/docs/appearance/ai-features).

## 3. 작성할 때의 실용적인 원칙

다음은 이 프로젝트에 적용할 편집 기준이다. 노출을 보장하는 순위 공식이 아니다.

- **주제를 먼저 설명하기**: 페이지가 누구에게 무엇을 제공하는지 명확히 쓴다.
- **검증 가능한 정보**: 수치·날짜·인용은 출처와 맞는지 확인한다.
- **사실과 해석 구분**: 원본 영상의 설명과 직접 작성한 의견을 구분한다.
- **명확한 구조**: 질문에 답하는 제목, 필요한 목록·표를 사용한다.
- **작성 주체 표시**: 영상 제작자와 사이트 운영자를 혼동시키지 않는다.
- **최신성 유지**: 수정한 경우 실제 변경 내용과 날짜를 맞춘다.
- **접근 가능한 본문**: 주요 설명을 이미지 안에만 넣지 않는다.

## 4. YouTube 학습 프로젝트에 적용한다면

현재 목표는 React와 API를 연결한 영상 서비스다. GEO를 이유로 불필요한 콘텐츠 생성 기능을 추가할 필요는 없다.

영상 상세에는 다음을 구분해서 보여준다.

| 정보 | 출처 |
| --- | --- |
| 영상 제목·채널·설명 | 실제 API 응답 |
| 원본 영상 링크 | 해당 영상의 실제 주소 |
| 직접 작성한 설명 | 사이트 작성자의 글임을 표시 |
| 정보 수정일 | 실제 변경이 있었을 때 기록 |

### 표현 예시

- 부정확한 표현: 영상을 확인하지 않고 “이 영상은 React를 완벽히 설명한다.”
- 근거를 구분한 표현: “채널에서 제공한 설명에 따르면 useState 입문을 다룹니다.”
- 직접 시청한 경우: “직접 시청 후 정리한 핵심 내용”이라고 표시하고 실제 내용만 작성한다.

이 예시는 작성 방식의 비교이며 실제 영상 평가가 아니다.

## 5. 피할 오해

- `aria-label`을 많이 붙이면 AI 노출이 좋아진다 → 근거 없음.
- 제목에 키워드를 반복하면 반드시 인용된다 → 보장 없음.
- 구조화 데이터를 넣으면 AI 답변 출처가 된다 → 보장 없음.
- `llms.txt`가 모든 AI 검색에서 요구하는 필수 파일이다 → 보편적 필수 조건이 아님.
- 크롤러 접근을 허용하면 학습·검색·답변 인용이 모두 같게 처리된다 → 서비스와 봇 목적에 따라 다름.

봇 접근 제어는 실제 배포 시 대상 서비스의 공식 문서를 확인한다.

## 6. 지금 할 것과 나중에 할 것

### 지금

- 실제 영상 정보와 원본 출처를 명확하게 표시한다.
- 제목·설명을 읽기 쉬운 본문으로 제공한다.
- 가짜 데이터·평가·제작자 정보를 만들지 않는다.

### 배포 후 검토

- 사이트가 공개 검색 대상인지 정한다.
- 검색엔진이 주요 콘텐츠에 접근할 수 있는지 확인한다.
- AI의 언급을 보더라도 한 번의 답변으로 성과를 단정하지 않는다.
